Project guide · photobook-transformer

From a folder of photos to a printed book.

A batch pipeline that turns a raw dump of photos into a curated, enhanced, captioned, print-ready photo book — event-type agnostic (a trip, a wedding, a baby's first year are all just Album + optional Segment). Fully offline by default; every external call is opt-in.

0

Install, once

Needs uv and Docker. Nothing else.

uv sync # .venv/ + deps
uv run pre-commit install
cp .env.example .env
1

Start the local stack

Brings up Immich, Prefect, and Postgres in Docker, then creates the app's tables.

uv run poe up
uv run poe migrate
2

Grab an Immich API key

Open http://localhost:2283, create the admin account (first visit only), then Account Settings → API Keys → New. Paste it into .env as IMMICH__API_KEY.

Optional: ANTHROPIC_API_KEY only unlocks --captioner claude — the default run needs no key at all.
3

Generate the album

Point one command at a directory of photos — it uploads them, creates the Immich album, derives album.yml, and runs every stage.

uv run photobook-generator generate ./path/to/photos
Options: --slug --title --timezone --force, and --source-document schedule.pdf to extract chapters from an itinerary/run-sheet.

Point it at a tree of albums and add --manifest to fan the folder into N independent books in one run — a root ingest.yml declares which subfolders are album vs. segment boundaries.

uv run photobook-generator generate ./photos-root --manifest # default: ./photos-root/ingest.yml
Fan-out is opt-in (a stray ingest.yml never changes plain generate <dir>); per-album fields live in the manifest, so --slug/--title/--source-document/--lead-face are rejected in this mode. A bad album is skipped and the run continues.
→ Book lands at data/albums/<slug>/book/index.html — open it in any browser. Prefer hand-authoring segments/lead_faces? Write album.yml yourself and run photobook-generator run --album <slug> instead. Watch either path live in Prefect at http://localhost:4200.
01 · Overall architecture A batch pipeline over Immich + Postgres

Immich stores and dedupes the raw photos, shared across all albums. Our Postgres is the source of truth for everything the pipeline computes — one row per photo, scoped by album_id — which makes every stage resumable.

Default path — offline, no keys Opt-in path — needs credentials

Why Prefect: per-photo retries + failure isolation across thousands of photos. Why PydanticAI: structured, bounded output (tone deltas, captions) with auto-retry on bad output. Since step 29: both are classical/offline by default (ClassicalToneEstimator + TemplateCaptioner); ClaudeCaptioner is opt-in.

02 · Stages flow A sequential spine, plus two concurrent fan-out groups

Ten stages turn Immich assets into a photo book, each its own Prefect task. Solid edges are hard data dependencies; the two shaded groups read only sync/select output and write disjoint state, so they run concurrently — each opening its own pooled DB session per worker thread. Diagram nodes carry a hover tooltip and the table below lists the concrete model/library behind each stage; this is the same document as knowledge/foundations/pipeline-execution.html, embedded live so the two can never drift apart.

03 · Process Test-driven, one branch per step, squash-merged

The order is fixed — checks → sub-agent review → user review → commit — and any change re-runs what precedes it.

  1. 1

    Take the next todo step from the progress tracker.

  2. 2

    Branch off main (step-NN-<slug>) — never commit to main; a no-commit-to-branch hook enforces it.

  3. 3

    Load the step's context and implement test-first.

  4. 4

    Get uv run poe check green (or the step's manual verification) before any review starts.

  5. 5

    Sub-agent review the diff — up to 4 broad-scope agents (2 adversarial correctness, 1 style/reuse, 1 architecture). Address comments, re-check, re-review until clean.

  6. 6

    User review — skipped per standing instruction; merges autonomously once checks + sub-agent review are clean.

  7. 7

    Squash into one <stage>: <what changed> commit, update the tracker + change log, fast-forward merge to main, push, delete the branch.

The commit gate — uv run poe check

ruff check+ ruff format --check+ basedpyright+ xenon (CC ≤ 5, grade A)+ pytest

Non-negotiable rules

generic — no trip/wedding concepts in src/ segments optional album_id first stage = its own Prefect task bounded tone deltas only config.py owns env vars idempotent stages alembic, never create_all()

Encoded as poethepoet tasks in pyproject.toml, triggerable via uv run poe <task>.

CommandWhat it does

uv run poe migratealembic upgrade head
uv run poe makemigration -- -m "…"alembic revision --autogenerate
uv run poe run -- --album <slug>run the pipeline flow for one album
uv run poe generate -- <dir>one-shot ingest: folder → Immich album → album.yml → run
uv run poe generate -- <dir> --manifestfan a folder tree into N albums via ingest.yml — one book each

Also a console entry point: uv run photobook-generator run --album <slug> / generate <dir> — poe run/poe generate just wrap it for symmetry with the other tasks.

Note The LAION-style aesthetic predictor + CLIP embedder (open_clip/torch) is the one deliberately deferred dependency — select's MMR has a tested fallback for missing scores/embeddings, so a run still completes with degraded curation quality until it's wired.
